# Room read — calibrate the survival model to the live draft room

Date: 2026-09-03
Status: spec — not started. Live draft assistant phase 7.

## Problem

`willLast` treats a player's real draft slot as `Normal(adp, clamp(adp·0.15,
4, 18))` — a smooth function of consensus ADP with no knowledge of *this* draft
room. But rooms differ a lot: one reaches four picks early on RBs and lets WRs
slide, another tracks ADP tightly, another is chaos. That's a first-order error
the static curve is blind to, and it's measurable from the picks already on the
board: `adpError = overall − adp` per pick tells you exactly how the room is
behaving vs consensus.

Fix: after ~8 picks, measure the room's bias and spread (overall and
per-position) and feed it back into the survival model and the recommendation
reasons. Most of it is arithmetic (`mean`/`stdev` of `adpError`); an optional
LLM layer interprets what arithmetic can't (a run *brewing*, the "why").

Sign convention: **negative `adpError` = the room reached** (drafted him earlier
than ADP).

## Scope

**In:**
- `src/draft/live/room.ts` (pure) — `analyzeRoom(state, board, settings) →
  RoomRead | null`: overall + per-position bias, spread multiplier, run
  pressure, a confidence that ramps with pick count, a one-line note.
- Wire into `willLast` (an optional adjustment param) and `computeAdvice` (apply
  it, add a "room is reaching X" reason + small confidence-scaled bump, attach
  `DraftAdvice.room`).
- `--room-read` flag on `npm run draft` (off by default until trusted); a Room
  read block in the render; the read captured in the recorder snapshot.

**Out (later phases):**
- The LLM interpreter overlay (phase 2 below) — structured but deferred.
- A `draft:review` "room read accuracy" section (phase 3).
- Using the room read anywhere but survival + the reach nudge (e.g. a full
  reach/wait strategy engine).

| Need | Existing piece |

## Approach

### 1. `RoomRead` — `src/draft/live/room.ts` (pure)

```ts
interface RoomRead {
  nPicks: number;              // ADP'd, non-keeper picks the read is based on
  confidence: number;          // clamp(nPicks / (teams * 2.5), 0, 1)
  overallBias: number;         // clamp(mean(adpError), ±BIAS_CAP); − = aggressive room
  spreadMult: number;          // clamp(sd(adpError) / expectedSd, SPREAD_MIN, SPREAD_MAX)
  positionBias: Partial<Record<Position, number>>;   // per-pos mean, positions with ≥ MIN_POS picks
  positionSpread: Partial<Record<Position, number>>; // per-pos, positions with ≥ MIN_POS_SD picks
  runPressure: Partial<Record<Position, number>>;    // last-round lean vs starter demand, 0–1
  note: string;                // "aggressive room (−3.1 vs ADP); reaching RB (−5), fading WR (+2); spread 1.3×"
}
```

```ts
analyzeRoom(state: DraftState, board: Board, settings: LeagueSettings): RoomRead | null
```

- Join `state.picks` (drop `keeper`) to `board.rows`; keep those with an `adp`.
  `< MIN_PICKS` (≈ 8) → return `null`.
- `overallBias` = clamped `mean(adpError)`.
- `expectedSd` = mean over those picks of the static `sigma(adp)`; `spreadMult`
  = clamped `sd(adpError) / expectedSd`.
- `positionBias[pos]` for positions with `≥ MIN_POS` (≈ 3) ADP'd picks; likewise
  `positionSpread[pos]` at `≥ MIN_POS_SD` (≈ 4).
- `runPressure[pos]` = over the last `teams` picks, `(count[pos] / window) −
  expectedShare[pos]`, floored at 0, where `expectedShare` comes from starter
  demand. A softer, forward-looking companion to `positionRuns`.
- `confidence` ramps to 1 by ~round 3 (`teams * 2.5` picks).
- `note` summarises for the render.

Constants (`BIAS_CAP ≈ 8`, `SPREAD_MIN 0.7`, `SPREAD_MAX 1.6`, `MIN_PICKS 8`,
`MIN_POS 3`) are module-level and get exported in the `record.ts` constant
bundle so a log stays self-describing.

### 2. Apply in `willLast` — `src/draft/live/survival.ts`

Optional third param, so every existing call and test is unchanged:

```ts
export interface RoomAdjust { adpShift: number; sigmaMult: number; }
export function willLast(adp: number | null, nextPickOverall: number, room?: RoomAdjust): Survival
```

- `effAdp = adp + (room?.adpShift ?? 0)` — a reached position has a negative
  shift, so `effAdp` drops and P(lasts) falls.
- `sigma = clamp(effAdp · FRACTION, FLOOR, CEIL) · (room?.sigmaMult ?? 1)`.

`survival.ts` stays ignorant of `RoomRead`/`Position` — the caller resolves the
numbers.

### 3. Apply in `computeAdvice` — `src/draft/live/assistant.ts`

- New input `roomRead?: boolean` (default off). When on: `const room =
  analyzeRoom(state, board, settings)`.
- Per scored row, build the `RoomAdjust`:
  - `bias = (room.overallBias + (room.positionBias[pos] ?? 0))`
  - `adpShift = bias * room.confidence`
  - `sigmaMult = lerp(1, room.spreadMult, room.confidence)`
  - pass into `willLast(row.adp, myNextOverall, { adpShift, sigmaMult })`.
- **Reach nudge:** if `room.positionBias[pos] <= REACH_THRESHOLD` (≈ −3) *and*
  the position has an open need, add `+ROOM_REACH_BUMP * confidence` to the
  score and a reason clause `"room is reaching ${pos} (${bias} vs ADP) — move
  now"`.
- Attach `room: RoomRead | null` to the returned `DraftAdvice`.

The LLM overlay (phase 2) is injected as a *separate* input
(`roomOverlay?: LlmRoomOverlay`) that `computeAdvice` merges onto the arithmetic
`RoomRead` before step 3 — so phase 1 needs no rework when phase 2 lands.

### 4. `DraftAdvice.room` + snapshot + render

- `types.ts`: `DraftAdvice.room: RoomRead | null`.
- `record.ts` `AdviceSnapshot`: carry `room` verbatim (small).
- `draft.ts` render, only when `--room-read` and `advice.room`:

```
Room read  (12 picks · conf 0.6)
  aggressive: -3.1 vs ADP overall · spread 1.3x
  reaching: RB -5, QB -6     fading: WR +2
```

### 5. CLI — `src/cli/draft.ts`

`--room-read` sets `computeAdvice({ …, roomRead: true })`. Nothing else changes;
the recorder already snapshots whatever advice it's handed.

## Phases

1. **Arithmetic room read** — `room.ts`, wire into `willLast` +
   `computeAdvice` + `DraftAdvice.room` + render + `--room-read`,
   `draft-room.spec.ts`. (~1 day)
2. **LLM interpreter overlay** — `--room-read-llm` (needs `ANTHROPIC_API_KEY`).
   One tool-forced call every `K` picks (≈ 5), cached under
   `.cache/room-read/<hash>.json`, input = the compact pick-vs-ADP table +
   league context, output = bounded `{ positionBias deltas, runForecast:
   Partial<Record<Position, "low"|"med"|"high">>, note }`. Merged onto the
   arithmetic read (deltas clamped, never replace). Same opt-in pattern as
   `newsDigest`. (~1 day)
3. **`draft:review` room-read accuracy** — `calibrate.ts` gains a pass: for each
   recorded `advice.room`, compare its `positionBias` to the actual mean
   `adpError` of picks *after* that event; report per-position error and a
   verdict on whether `--room-read` earns default-on. (~0.5 day)

## Testing

- `analyzeRoom` against synthetic pick lists (built in-test, like
  `draft-calibrate.spec.ts`): a room that drafted everyone 4 early →
  `overallBias ≈ −4`; RB picks all −6 / WR all +2 → `positionBias` recovers
  both; wide scatter → `spreadMult > 1`; `nPicks < MIN_PICKS` → `null`; a keeper
  with a huge negative error is excluded.
- `willLast(adp, next, { adpShift: −5, sigmaMult: 1 })` returns a lower `prob`
  than `willLast(adp, next)`.
- `computeAdvice({ roomRead: true })` on a fixture where the room reached a need
  position: that player's rec carries the "room is reaching" reason and
  outscores an equal-value player at a faded position.
- Back-compat: existing `draft-survival.spec.ts` / `draft-assistant.spec.ts`
  pass unchanged (room params are optional and default off).
- All pure — no network in phase 1.

## Open items / risks

- **Overfitting a lucky start.** 12 picks is few; two RB-happy managers ≠ "an RB
  room." Bounding (`BIAS_CAP`), the `confidence` ramp, and applying `bias *
  confidence` all damp it. The read is a weak prior at pick 12 that firms up by
  pick 30.
- **The useful window is picks ~12–25.** Before: noise. After: the static model
  has enough picks of its own. Real but narrow — rounds 2–3, where the decisions
  matter.
- **Keepers must be filtered** from the room analysis (`pick.keeper`) — a keeper
  at round 5 with ADP 30 is a −60 adpError that would wreck the mean.
- **Sign errors are easy here** — negative `adpError` = reach, negative
  `positionBias` → lower `effAdp` → less likely to last. Tested explicitly.
- **Per-position spread needs samples** — `positionSpread` only for positions
  with ≥ 4 ADP'd picks; otherwise fall back to the global `spreadMult`.
- **Scope creep toward a strategy engine.** Phase 1 touches only survival + one
  reason clause + one small bump. "Should I reach / trade back / punt QB" is a
  separate spec.
- **Default-on decision** deferred to phase 3's accuracy report against a real
  draft log.
